## 建议下一位开发者首先做

1. 按 README 克隆、安装依赖、测试和构建。
2. 基础界面已获用户确认；继续记录刷新、重开聊天等细分场景结果。

## 交接记录规则

每个 PR 更新本文件，写明完成事项、测试命令与结果、未解决问题及下一步。多人各自使用分支，避免同时修改同一文件。不要把“本地测试通过”写成“客户端或远端 CI 验收通过”。

## 本轮验证补充

浏览器检查新增模拟 MCP Apps 宿主，覆盖初始化、工具结果推送、软件详情与搜索、刷新工具调用及错误后的按钮恢复。测试数据仅在浏览器测试宿主中注入，不进入产品清单。模拟检查不替代真实客户端验收。

下一项建议：登记软件及路径配置；真实生信任务仍需选定软件和示例数据。

## 软件卡片重排

保留名称与简介，添加引用论文、版本、官方地址和操作四个可展开入口。引用区支持按已有字段复制标题、完整引用及 BibTeX；版本区分别展示实际版本和最新稳定版；地址仅接受 HTTP/HTTPS 并支持打开与复制。操作为预留页面，尚不执行任务。空清单下展示明确标注的结构占位卡片，不计入登记数量。已通过四入口切换、搜索、刷新、窄屏及 MCP 基础测试。

## 版本入口

按用户要求，卡片“版本”入口展示当前对话宿主版本，而不是外部生信软件版本。每次点击均重新调用 get_client_version，不缓存结果；最新稳定版本固定标注为 V1.0（当前插件版本）。内部开发构建标识仍为 0.1.0。

- MCP Apps 宿主明确报告 web 时返回 Web。
- Windows desktop 宿主：仅沿当前 MCP 进程的活跃父进程链定位 OpenAI ChatGPT/Codex 应用，再按可执行路径匹配当前用户 Windows 应用包，读取包版本。不会扫描并选取其他无关 GPT 客户端。
- 未识别宿主、客户端未运行、权限不足、非打包桌面安装或检测失败显示 Error。独立 localhost 预览也为 Error，不冒充 ChatGPT 网页端。
- 不使用可执行文件的 FileVersion/ProductVersion：实测它们可能是 Chromium 引擎版本。
- 本机读取结果：26.1013.4894.0；已验证连续点击重新查询、旧结果失效、Web 和 Error 分支。更新后仍需在真实客户端验证宿主 platform 字段是否提供；缺失时按要求返回 Error。
